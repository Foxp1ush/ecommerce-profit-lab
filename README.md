# 이커머스 수익성·신기종 초도 발주 대시보드

> 여러 판매 채널에서 **상품마다 실제로 얼마가 남는지** 보고, 신기종 출시 때 **첫 발주를 몇 개 할지** 정하는 대시보드.
> 가상 스마트폰 액세서리 브랜드 '그립앤코'의 **가상 데이터**로 만들었습니다. 수수료율·물류비·환율 등은 모두 **가정값**이며 화면에서 바꿀 수 있습니다.

## 무엇을 하나
| 화면 | 설명 |
|---|---|
| 수익성 개요 | 순매출에서 수수료·물류·반품·광고·원가가 빠져 **공헌이익**이 되는 과정(워터폴), 채널별 남는 몫, 월별 추이 |
| SKU 진단 | 판매량 × 이익률 산점도로 **"많이 팔리지만 손해 보는 상품"**을 찾고, 손해 원인(광고비·반품·수수료·물류비)을 자동 판별 |
| 가정값 | 채널 × 카테고리 수수료율, 채널 × 크기 등급 물류비를 표에서 고치면 모든 화면이 다시 계산됨. 환율·수입 부대비용·반품 재판매율도 조정 |
| 초도 발주 시뮬레이터 | 과거 출시 6회를 회귀해 신기종 수요를 범위로 예측 → 품절 손실과 재고 손실을 비교(신문팔이 모형)해 권장 물량, 색상·모델별 발주 수량 |
| 데이터 보기 | 표 둘러보기, 읽기 전용 SQL 직접 실행(조회만 허용, 5초·1,000행 제한) |

## 데이터 (모두 가상)
- 채널 5개: 쿠팡 · 스마트스토어 · 자사몰 · 아마존 미국 · 아마존 일본
- 상품 126개(케이스·강화유리·그립·거치대·충전기), 1년 일별 판매 약 4.8만 행, 월별 환율, 과거 출시 6회
- 이익은 공급가액 기준. 원·달러·엔 통화 차이 반영
- 실제 회사의 상품명·로고·수치는 쓰지 않았습니다. 기종 이름은 출시 시점을 흉내 내려고 빌린 것뿐입니다

## 검증 (가상 데이터 기준)
- **진단 로직**: 원인을 알고 일부러 심어 둔 손해 사례 5건을 모두 찾고 원인까지 맞히는지로 확인
- **초도 발주 백테스트**(출시 1회씩 빼고 예측): 평균 오차 8.6%, 놓친 이익이 "직전 출시만큼 주문" 대비 약 76% 적음

### 만들면서 고친 것
- 수수료·물류비를 채널마다 한 값으로 넣었다가, 실제로는 카테고리별 수수료표와 상품 크기별 물류비가 다르다는 점을 반영해 고쳤다
- 처음 예측 모형은 80% 예측 범위의 적중률이 58%로 **실제보다 자신만만**했다. 한 출시의 케이스·강화유리를 독립된 증거로 따로 센 것이 원인 → 출시 단위로 회귀를 바꿔 75%로 개선

자세한 과정과 결정 이유는 [`WORKLOG.md`](WORKLOG.md)에 있습니다.

## 만든 방식
생성형 AI(Claude Code)로 구현했습니다. 무엇을 볼지, 어떤 가정과 계산 기준을 쓸지, 결과를 어떻게 검증할지는 직접 정했습니다.

## 실행
```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m streamlit run app.py
```
- 처음 실행하면 `data/lab.db`에 가상 데이터를 만든다(고정 시드라 항상 같은 데이터). 지우면 다시 만든다
- Python 3.13 기준

## 테스트
```bash
.venv\Scripts\python.exe -m pytest -q
```
31개: 같은 시드 = 같은 데이터, SQL 합계 = 원본 합계, 이익 항목 합계, 심어 둔 사례 진단, 가정값 반영, 수요·물량 방향성, 백테스트, 위험한 SQL 거부, 화면이 오류 없이 뜨는지를 확인한다.

## 구조
- `app.py` — Streamlit 화면
- `assumptions.py` — 가정값(수수료·물류비·반품·환율·리드타임)을 한곳에
- `generate.py` — 고정 시드 가상 데이터 생성
- `db.py`, `sql/` — SQLite와 집계 쿼리
- `profit.py` — 공헌이익 계산과 손해 원인 진단
- `launch.py` — 수요 예측, 초도 물량, 백테스트
- `SQL_연습노트.md` — SQL 기본 문법을 엑셀 기능과 비교한 학습 노트
- `WORKLOG.md` — 날짜별 작업 기록
